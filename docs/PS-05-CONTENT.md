Экран кейсов содержит спокойное ожидание материалов; 06.* сохранены. Ошибка изображения показывает alt на нейтральной поверхности, изображения имеют заданные размеры.

## Локальное сравнение R12

- A: `http://127.0.0.1:3001/?review=ps05&caseMotion=A#screen-04`
- B: `http://127.0.0.1:3001/?review=ps05&caseMotion=B#screen-04`

Параметр `review=ps05` действует только на localhost / 127.0.0.1 / ::1. Обе версии открывают один `REVIEW_CASE` с явной маркировкой «макет / не реальный кейс». A — базовый переход; B — визуальный перенос одной обложки к тому же native dialog. В reduced motion B становится A. `?case=<id>#screen-04` — адрес детализации; никакие контактные данные туда не попадают.

## Транспорт

Внешнего endpoint и юридического текста в репозитории нет. Обычная форма не отправляет данные и не показывает фиктивный успех. Имя, телефон/Telegram и бриф остаются в памяти текущей вкладки; закрытие формы их сохраняет, перезагрузка начинает новую сессию.

`app/_ps05/transport.ts` содержит типизированный `Inquiry`, `Receipt`, проверку полей, `createHttpTransport`, `unavailableTransport` и локальный `createTestTransport`. Для реального подключения:

1. Предоставить same-origin серверный endpoint и серверную конфигурацию канала доставки.
2. Сервер должен валидировать payload, ограничивать частоту запросов, дедуплицировать `requestId` / `Idempotency-Key`, возвращать `{ accepted: true, receiptId: "…" }` только после принятия запроса. HTTP 200 без квитанции не считается успехом.
3. Добавить утверждённые privacy/contact в `siteContent`, затем подключить HTTP-адаптер в `Experience` и его `available`-условие. Сейчас публичный режим намеренно использует `unavailableTransport`.
4. Проверить в согласованном sandbox; отправка реальной заявки и внешняя настройка не выполнялись.

Локальная проверка: `?review=ps05&transport=success` либо `transport=retry` (первый вызов — тестовый отказ, второй — подтверждение). Всё исполняется в браузере без сетевого POST. Формулировка успеха прямо говорит, что настоящая заявка не отправлялась. Это доказательство поведения интерфейса и адаптера, не доставки письма.

## Редактура

В `catalog.ts` помечено `status: editorial-draft`; владелец может уточнить результаты компетенций, примеры форматов, цели задач и связующие формулировки. IDs и UI-порядок не менять без миграции. Нужно подтвердить финальные коммерческие тексты, факты «О нас», границы услуг, юридический текст и доступные каналы обращения.

Локальные проверки наполнения: ?review=ps05&content=sample#screen-06.1 (явно маркированные макеты), ?review=ps05&media=broken#screen-04 (ошибка изображения). Ни один из этих материалов не попадает в обычный публичный режим.
