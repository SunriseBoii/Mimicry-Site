# PS-05 — результат реализации

PS-05 интегрирован в основную страницу `/`. Посетитель выбирает один из двух крупных входов: собирает проект через задачу и компетенции либо сразу переходит к нужной экспертизе. Сводка и примеры работ помогают сформулировать редактируемый запрос. Контактный шаг показывает точный текст и состав, сохраняет введённое и обрабатывает ошибки.

Основа: `master`, `c339450363eb06f4363e33d2d4f639f32c5a28ff`. На старте дерево чистое. Результат — локальные незакоммиченные изменения, без push/публикации. Проверка агента не является HUMAN PASS владельца.

## Запуск и просмотр

```powershell
npm.cmd run build
npm.cmd run start -- --hostname 127.0.0.1 --port 3001
```

- A: http://127.0.0.1:3001/?review=ps05&caseMotion=A#screen-04
- B: http://127.0.0.1:3001/?review=ps05&caseMotion=B#screen-04
- Проверка ошибки/повтора формы: http://127.0.0.1:3001/?review=ps05&transport=retry

## Проверки и воспроизводимость

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
$env:PS05_BASE='http://127.0.0.1:3001'
$env:PS05_RUN='new-review-run'
node scripts/ps05-browser-qa.mjs
node scripts/ps05-extra-qa.mjs
node scripts/ps05-performance.mjs
```

Основной браузерный проход: **98 captures/checks**, **0 runtime errors**. Edge headless / Playwright Core, ANGLE D3D11, локальный production build. Матрица: 1440×900 — 18 экранов в двух темах; 1280×720, 390×844, 360×800, 320×800, 844×390 — ключевой путь, форма и кейс. У снимков есть manifest с viewport, темой, node, состоянием GPU и числом Canvas. Переполнение по ширине проверяется автоматически. Canvas сохраняет DOM identity через весь основной desktop-путь. Axe: 0 нарушений на главной, брифе, мобильной форме и в финальной проверке обеих тем сразу после переключения (правила WCAG A/AA). Промежуточный аудит нашёл краткий провал контраста во время перехода фона; он исправлен и повторно проверен.

Полный набор тестов: **436/436**. После финальных правок повторены 7 профильных тестов PS05. TypeScript и production build проходят. Lint: 0 ошибок, 16 существовавших до PS05 предупреждений. `git diff --check` проходит. Frozen public assets, shader/geometry/material/camera, resolver, motion compiler и PS04 goldens не изменялись; дорогая регенерация 3D не запускалась.

Основные исправления: ручной бриф больше не перезаписывается; длинный контент доступен; номер из дефисов не проходит валидацию; доступное имя поля отделено от подсказки; дробная последняя точка маршрута достижима; deep-link не оставляет активный экран inert. В B устранено одновременное отображение исходной/конечной обложек под анимируемой копией. На 320 px добавлен воздух внутри обложки.

Мобильные и короткие экраны используют естественный поток. На большом desktop горизонтальные группы остаются при достаточной высоте содержания; когда раскрытые материалы не помещаются, применяется тот же измеряемый поток. Это сознательная адаптация без скрытия информации и уменьшения основного кегля.

## R12: рекомендация

Оставлен A по умолчанию. Он быстрее переводит внимание к содержанию, не масштабирует текстовую обложку и проще при разной пропорции изображений. B даёт наглядную связь карточки и детализации; на реальной фотографии такой эффект можно оценить лучше. Он реализован полностью, но требует окончательного выбора владельца после просмотра. Оба используют одинаковый контент и один native dialog, поддерживают URL/history и возврат фокуса. В reduced motion B открывается как A.

## Данные и внешние зависимости

Подключение описано в [PS-05-CONTENT.md](PS-05-CONTENT.md). Основная точка — `app/_ps05/content.ts`: кейсы/обложки/галереи/видео; команда и портреты; партнёры/клиенты и разрешённые логотипы; отзывы с подтверждённой атрибуцией; реальная презентация, прямой контакт, privacy и текст согласия. Каталог услуг/примеров/целей для редактуры — `catalog.ts`.

**Реальные заявки не отправляются.** В репозитории нет внешнего endpoint и согласованного юридического текста. Обычный режим честно показывает недоступность отправки и позволяет сохранить бриф. Тестовый transport существует только в локальном review; он не делает POST. Его успех доказывает поведение UI, а не доставку заявки. HTTP-адаптер подготовлен и требует явную серверную квитанцию, серверную валидацию, rate limit и дедупликацию requestId.

Проверки проведены на этой Windows-машине в Edge. Физические iOS/Android-устройства, Safari/Firefox, screen reader и реальная внешняя доставка не проверялись. 200% проверяется эквивалентным CSS viewport 720×450 при DPR 2; это не ручное управление browser zoom. 320 CSS px проверяет reflow широкого viewport при 400%. Лабораторные метрики не являются полевыми Web Vitals и не доказывают производительность всех GPU. Пользовательское исследование не проводилось; визуальная оценка — экспертный просмотр агента.

## Финальный просмотр и производительность

Просмотрены все desktop contact sheets, адаптивные sheets и проблемные кадры в полном размере. Иерархия и два входа читаются быстро; четыре тезиса выбранного набора видны одновременно; примеры работ отделены от выбора; CTA доступен на длинном экране; пустые trust-секции не выдают макеты за факты. Мобильные акторы проверены в их собственной позиции после содержания. Финальный диалог при 320 px не имеет внутреннего горизонтального переполнения.
